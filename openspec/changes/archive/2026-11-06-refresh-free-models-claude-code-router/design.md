## Context

Четыре discovery-команды имеют одинаковые параметры и форматы, но различаются API, схемами каталогов и правилами бесплатности. Эти различия уже инкапсулированы внутри команд. Refresh работает с конфигом CCR через management RPC и не должен становиться вторым местом реализации catalog-логики.

## Goals / Non-Goals

**Goals:**

- обнаруживать платформы по именам исполняемых discovery-команд;
- разрешать явный comma-separated subset с валидацией и дедупликацией;
- получать таблицу, ids и карту размеров только через CLI выбранной команды;
- идемпотентно создавать/обновлять отдельный провайдер CCR на платформу;
- обновлять только управляемые модели и credentials, сохраняя ручные данные;
- выполнять один save и один restart на агрегированный прогон.

**Non-Goals:**

- повторная реализация HTTP-загрузки или разбора provider-каталогов в refresh;
- inference-запрос к каждой модели;
- изменение пользовательских провайдеров, не совпадающих с известными base URL;
- управление dsh-конфигурацией.

## Decisions

1. **Discovery по имени файла.** Платформа извлекается из `get-free-models-<name>.sh`; общий движок имеет имя, не попадающее под этот glob.
2. **CLI как единственная граница данных.** Refresh вызывает для каждой платформы форматы `table`, `json-ids` и `sizes`. Он не содержит catalog URL, правил бесплатности или HTTP-кода каталогов.
3. **Metadata отдельно от catalog-логики.** Имя CCR-провайдера, inference base URL и имя переменной ключа задаются компактной таблицей платформ внутри refresh. Это конфигурация назначения, а не дублирование discovery.
4. **Управляемые записи имеют namespace.** Credentials получают id `env-free-models-<platform>-*`; только такие записи заменяются. Список моделей заменяется целиком только у управляемых провайдеров, потому что discovery-команда является источником актуального free-набора.
5. **Атомарная агрегация.** Все изменения строятся в одном JSON, валидируются и сохраняются единственным RPC-вызовом. Перезапуск выполняется один раз после успешной верификации.

## Risks / Trade-offs

- [Новый discovery-скрипт без CCR metadata] → fail-fast до изменения конфига с понятным сообщением о неподдерживаемой платформе.
- [Один каталог недоступен] → весь агрегированный прогон прекращается, старый конфиг не сохраняется.
- [Пользователь переименовал провайдера] → совпадение выполняется по base URL; display name не используется как идентификатор существующего провайдера.
- [Ключ отсутствует] → модели синхронизируются, существующие credentials не удаляются; в выводе появляется warning.

## Migration Plan

Старые имена файлов и симлинков заменяются новыми в одной волне. После GREEN acceptance refresh запускается на работающем CCR со всеми обнаруженными платформами. Откат выполняется возвратом коммита и восстановлением последнего JSON-бэкапа через management RPC.
