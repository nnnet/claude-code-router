## Purpose

Определяет совместимый CLI-контракт для обнаружения бесплатных моделей нескольких router-провайдеров без изменения вызывающих скриптов и парсеров результатов.

## ADDED Requirements

### Requirement: REQ-PFM-001 Совместимые команды и параметры
Система SHALL предоставлять отдельные команды для OrcaRouter, TeamoRouter и Kilo Gateway. Каждая команда SHALL принимать параметры `--format`, `--limit`, `--sort`, `--with-endpoints`, `--endpoints-concurrency`, `--cache-dir`, `--max-age`, `--max-age-endpoints`, `--refresh`, `--offline`, `--help` с семантикой, совместимой с `openrouter-free-models.sh`.

#### Scenario: Одинаковая поверхность CLI
- **WHEN** пользователь запрашивает справку любой из трёх команд
- **THEN** команда перечисляет одинаковый набор поддерживаемых параметров и провайдер-специфичные переменные окружения

### Requirement: REQ-PFM-002 Корректное определение бесплатных моделей
Система SHALL определять бесплатные модели по явным признакам соответствующего провайдера: бесплатным идентификаторам и нулевой цене OrcaRouter, суффиксу `-free` TeamoRouter, полю `isFree` Kilo Gateway. Бесплатные виртуальные маршруты провайдера SHALL включаться, если каталог явно обозначает их бесплатными.

#### Scenario: Нормализация разных каталогов
- **WHEN** команды получают эквивалентные fixtures каталогов трёх провайдеров
- **THEN** каждая команда возвращает только модели, явно отмеченные бесплатными по правилам своего провайдера

### Requirement: REQ-PFM-003 Совместимые форматы результата
Каждая команда SHALL поддерживать форматы `table`, `json`, `ids`, `json-ids`, `sizes`. Форматы SHALL сохранять названия полей, единицы измерения, сортировку, ограничение числа моделей и размещение account summary, совместимые с `openrouter-free-models.sh`.

#### Scenario: Машиночитаемые форматы
- **WHEN** пользователь выбирает любой машиночитаемый формат
- **THEN** stdout остаётся валидным результатом выбранного формата и не содержит диагностических сообщений

### Requirement: REQ-PFM-004 Кэш и offline-режим
Каждая команда SHALL кэшировать каталог в отдельном каталоге провайдера, учитывать TTL, поддерживать принудительное обновление и SHALL завершаться кодом 2 при отсутствии пригодного кэша в offline-режиме.

#### Scenario: Повторный offline-вызов
- **WHEN** каталог был успешно закэширован, а затем команда вызывается с `--offline`
- **THEN** команда возвращает тот же набор бесплатных моделей без сетевого запроса

### Requirement: REQ-PFM-005 Безопасное использование API-ключей
Команды SHALL получать ключ только из переменной окружения, имя которой задаётся провайдер-специфичной настройкой. Значение ключа MUST NOT передаваться как аргумент процесса, записываться в кэш или попадать в stdout/stderr.

#### Scenario: Ключ отсутствует
- **WHEN** переменная ключа пуста, а публичный каталог доступен
- **THEN** команда возвращает каталог и помечает account-specific сведения неизвестными без раскрытия секретов

### Requirement: REQ-PFM-006 Неизвестные метрики не фабрикуются
Если провайдер не публикует endpoint health, latency, throughput или персональные quota counters, команда SHALL возвращать соответствующие поля как `null`, ноль только для документированного пустого количества, либо `—` в таблице. Команда MUST NOT выводить синтезированные показатели как измеренные.

#### Scenario: Запрос endpoint-метрик без API провайдера
- **WHEN** пользователь передаёт `--with-endpoints` провайдеру без публичного API метрик
- **THEN** формат результата сохраняется, а недоступные метрики имеют неизвестные значения
