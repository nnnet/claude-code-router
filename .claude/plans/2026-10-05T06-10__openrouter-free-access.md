# openrouter-free-models.sh — срок жизни и доступ для пользователя

Дата: 2026-10-05. Запрос: во всех форматах выводить дату экспирации модели и
доступность для запрашивающего пользователя (остаток запросов, закрыта ли
модель). Сначала API, парсинг страниц — только где API молчит.

Файл в проде: `~/.local/bin/openrouter-free-models.sh` — симлинк на
`scripts/openrouter-free-models.sh`, поэтому любая правка репо-файла сразу
боевая. Разработка — в `scripts/openrouter-free-models.next.sh`.

## Источники (проверено запросами)

| Сведение | Откуда | Ключ |
|-|-|-|
| дата экспирации | `/api/v1/models` → `expiration_date` | нет |
| состояние провайдеров | `/api/v1/models/<id>/endpoints` → `status` (0 — работает), `uptime_last_5m` | нет |
| открыта ли модель пользователю | `/api/v1/models/user` (учитывает настройки приватности и провайдеров) | да |
| free-запросы за сутки | `/api/v1/key` → `free_model_daily_requests {used,limit,remaining}` | да |
| free-запросы в минуту | API не отдаёт; исходник документации `limits.md` → `FREE_MODEL_RATE_LIMIT_RPM` | нет |

`per_request_limits` в каталоге пуст у всех моделей — не используется.

## Договор с потребителями

`zed.sh`, `scripts/dsh-refresh-free-models.sh`, `scripts/refresh-free-models.sh`:
`json-ids` — массив строк, `sizes` — объект с `.ctx/.total/.active/.tokens`.
Эти поля и форма не меняются; в `sizes` добавляется только `access`. Для
`ids`/`json-ids` сведения о доступе идут сводкой в stderr.

## Ключ

Скрипт знает только имя переменной (`OPENROUTER_KEY_ENV`, по умолчанию
`OPENROUTER_API_KEY`). Значение подставляет curl (`--variable %ИМЯ`,
`--expand-header`). Переменная пуста — запросы с ключом не делаются вовсе. Из
ответа `/api/v1/key` в кэш попадают только счётчики: поле `label` содержит
фрагмент ключа.

### A1 `research` — источники данных
- выход: таблица источников выше
- приёмка: каждое поле подтверждено живым запросом или исходником документации
- заметки: сделано

### B1 `implement` — доработать копию
- выход: `access` для каждой модели во всех форматах
- приёмка: `bash -n`, все пять форматов отрабатывают с ключом и без
- заметки: сделано. Ветки «истекла», «закрыта», «лимит», «ключ отвергнут»
  проверены на локальной подделке API с поддельным ключом; «недоступна» — на
  живых данных (статус `-2`)

### C1 `compat` — договор с потребителями не нарушен
- выход: сравнение старого и нового вывода
- приёмка: `ids`, `json-ids` побайтово равны; в `sizes` старые поля равны;
  прогон `zed.sh` с новой копией даёт тот же `available_models`
- заметки: сделано. Первый прогон `zed.sh` упал: `access` для всех 466 моделей
  раздул `sizes` до 153 КБ, а `zed.sh` передаёт его в python одним аргументом
  (предел 128 КБ). Теперь `access` в `sizes` только у free-моделей — 59 КБ;
  `settings.json` после старой и новой версии совпадает целиком

### C2 `secrets` — ключ не утекает
- выход: проверка вывода, кэша и списка процессов
- приёмка: в выводе и кэше нет значения ключа и поля `label`; без ключа
  запросов к `/key` и `/models/user` нет
- заметки: сделано. Без ключа сервер получил только `/models` и `limits.md`;
  поле `label` из ответа подделки в кэш не попало

### D1 `replace` — замена прод-файла
- выход: прод-файл заменён, копия старого сохранена, коммит и пуш
- приёмка: прод-вызов из запроса отрабатывает
- заметки: сделано; старая версия — `scripts/openrouter-free-models.sh.bak-20261005`

### E1 `english-units` — английский вывод и единицы измерения
- выход: заголовки и значения вывода только на английском; в таблице единицы
  в шапке, в ячейках голые числа; в json и sizes у каждого числа пара
  `<key>_unit`
- приёмка: `ids`, `json-ids` и старые поля `sizes` равны прежним; `zed.sh`
  даёт тот же `settings.json`; ветки вердиктов на подделке API
- заметки: сделано. Единицы цен взяты из документации; у `audio*` и
  `image_output` единица там не названа — пары нет. `sizes` с единицами в
  прежнем виде занял 118 КБ при пределе аргумента 128 КБ, поэтому отдаётся
  компактным JSON: 90 КБ. Копия предыдущей версии —
  `scripts/openrouter-free-models.sh.bak-20261005-0640`
